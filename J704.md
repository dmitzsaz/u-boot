# J704 / M5 fork

The `main` branch starts from the tested upstream commit
`8295be11f8950b23737d834faa75e5dd9f616ba4`. Target: Mac17,2 / J704AP / T8142.

Changes cover bounded J704 USB2 host initialization and OS handoff, MTP
RTKit startup and live DMA-buffer reservations, validated kernel placement,
and UART receive-FIFO handling. The USB2 host PHY path covers all three
external Type-C ports, including the former bring-up UART port. DART support
here admits only the tested hardware bypass path for T8142.

The source combination was built and used in the v15 loader, verified by
native boot on J704, keyboard/trackpad handoff and USB host use. Its USB2
bootloader path does not establish bootloader SuperSpeed or DP support.
Linux supplies the later display and USB-C implementation.
The newly enabled first Type-C port has passed source tests and a full build;
USB storage enumeration on that port still needs hardware verification.

T8142 NVMe wakes iBoot's quiesced ANS firmware without a CPU reset. Before
the first NVMe scan, J704 runs the shared storage power producer and requires
each inherited storage domain to be actually active. The same one-shot
producer serves the later SD startup; PMP starts in Linux. Linear submission
queues use the separate NVMMU register window. Only namespace 1 is exposed.
Before OS boot, U-Boot retires its I/O queues, reserves its live DMA buffers
and publishes `nvme-running-v1`. Linux must support that handoff before this
U-Boot is installed. A failed startup disables the OS storage node while
preserving firmware buffers. The corrected power ordering, SSD enumeration
and Linux adoption were exercised by native J704 boot from the internal SSD.

## Encrypted boot

The optional `luks` command provides read-only mappings for LUKS2
AES-XTS-plain64 with Argon2id or PBKDF2, 512- or 4096-byte sectors and a
single supported dynamic segment/digest. Other layouts are rejected. The
implementation imports Simon Glass / Canonical's LUKS, blkmap and JSON code
and the Argon2 reference implementation from
`deinde-dev/deinde-concept-u-boot` at
`65facf3465de607af3191438d60beed7aab65e60`, retaining their attribution.
The J704 adaptations add metadata bounds/checksum checks, read-only mappings,
4Kn handling, hidden passphrase input and key cleanup.

The owner-selected `aurora,luks-partition` and `aurora,luks-bootargs` chosen
properties select this boot path. U-Boot reads the kernel and initramfs from
the encrypted Btrfs filesystem, destroys the mapping and clears its key
before entering Linux. It neither formats the disk nor changes LUKS slots.
Linux unlocks the root independently, so it asks for the passphrase again.
No SD card or separate unencrypted boot partition is required.

The full ARM64 build and ten sandbox integration cases passed, including
512/4096-byte devices, encrypted Btrfs/zstd reads, incorrect passphrases,
invalid metadata and boot-script failure paths. Native boot then loaded
the kernel and initramfs from the internal LUKS2/Btrfs root successfully.

A matching [Aura](https://github.com/dmitzsaz/aura) and board DT are required.
Raw ADTs, firmware, machine calibration, boot-specific DTBs and boot binaries
remain outside this repository. This development snapshot is not a generic
installer or permission to change a machine's boot policy.

See [Linux](https://github.com/dmitzsaz/linux) for the driver snapshot and
its firmware/DT requirements.

## Board source and SD boot

`dts/upstream/src/arm64/apple/t8142-j704.dts` and its platform include mirror
the Linux board source. `apple_j704_defconfig` selects the normal J704 build,
MTP input and its Genesys GL9755 SD reader behind PCIe port 2.

The SD path performs bounded power/PHY/link startup, configures the endpoint
and uses an owned DART identity map for ADMA when the stream is dormant. Before
OS handoff it stops the reader's DMA, retires its DART mapping and clears the
root-port enumeration windows, retaining the powered link for Linux to adopt.
A partial startup cannot be replayed. All eight SD-path PCIe tuning tables
come from Aura's validated format-1 `/j704-platform-data` contract; there is
no compiled per-machine tunables header.

The default `j704_sdboot` command reads `/boot/extlinux/extlinux.conf` from
`mmc 0:1`; environment variables can select a different card partition or
configuration path. Use the prepared DT inherited from Aura. An extlinux
`FDT`/`FDTDIR` entry that reloads the raw board DT discards firmware, memory
and calibration fixups. The generic extlinux fallback already supports
`fdtcontroladdr` when no replacement DT is requested.

The original SD implementation was used in the working native boot package.
This version's live-table consumer passes a valid-contract case and 34 refusal
cases under ASan/UBSan, and the complete J704 U-Boot image builds with GNU
binutils. The combined new Aura/DT/Linux handoff still needs a hardware boot.
Build/install recipes and private owner profiles remain outside the repository.

## Selecting a coordinated kernel and DT update

An optional `/chosen/aurora,sd-extlinux-conf` string selects an extlinux
configuration for this boot object, unless a saved environment already sets
`j704_sdconf`. With an explicit selection the default boot command does not
scan for other boot configurations if the selected one fails. This lets an
installer stage a new kernel/initramfs/DT contract while preserving the previous
boot object's normal extlinux configuration for rollback. No partition layout
or persistent U-Boot environment change is required.
